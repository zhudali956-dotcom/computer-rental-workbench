# 架构与数据边界

工作台是面向单台办公室主机的应用。React 静态文件与 API 由同一个 Express 服务提供。SQLite 负责用户、线索归属、商机、内容版本及待同步队列。飞书多维表是同步后的查看和汇总视图。

| 路径 | 数据怎么流动 |
|---|---|
| 导入与领取 | CSV/XLSX 先预览、去重并记录来源。新线索在飞书确认后进入公共池。领取、归属与待同步操作在本地事务中完成。 |
| 联系与回访 | 联系、商机与回访分开保存。拒绝联系会原子标记勿扰、取消回访。 |
| 飞书同步 | 通过业务 ID、版本与快照对账。写入回执丢失时先查证再重试。直接编辑受控字段导致差异时进入冲突处理。 |
| 内容运营 | 审核引用固定的稿件版本、账号和素材。平台草稿凭证与公开发布状态独立。二进制素材留在本地库，飞书同步元数据。 |
| 失败恢复 | 备份使用一致性快照并加密。正式库恢复至新路径后先只读，远端一致性检查通过后再切换。 |

工作台账号分为管理员和员工。员工的运营能力由具体社媒账号授权决定。登录会话、平台登录态和接口凭据不属于飞书业务数据。正式部署使用一台主机和一组写入凭据。

主要入口：`server/index.mjs` 组装服务，`server/http.mjs` 注册销售和管理接口，`server/content-http.mjs` 注册内容接口，`server/feishu.mjs` 执行同步。销售数据逻辑在 `server/store.mjs`，内容数据逻辑在 `server/content.mjs`。
